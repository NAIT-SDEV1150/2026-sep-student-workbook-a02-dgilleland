Component State Management - Course Status

Guided Self-Study Tutorial

Section titled “Guided Self-Study Tutorial”

In the previous custom element homework, we worked with styling hooks for <course-info>. In this self-study tutorial, we’ll move the component one step further: it will manage its own state.

The page will pass a full course object into each <course-info> card. The component will render that course, track whether the course is Not Enrolled, Enrolled, or Completed, and tell the page when that status changes by dispatching a custom event.

There are a few important details here.

STATUSES.includes(value) protects the component from unknown status values. If someone calls card.setStatus('Waiting List'), the component normalizes that back to null.

When the status is null, we remove the status attribute. When it is 'Enrolled' or 'Completed', we set the attribute. The CSS in the template uses that attribute to move the visual switch and style the card.

The custom event uses bubbles: true and composed: true. That lets the event move through the Shadow DOM boundary so the containing page can listen on #course-list.

Common Lifecycle and State Problems

Section titled “Common Lifecycle and State Problems”

If something is not working, use the symptom to narrow down the problem.

SymptomWhat to check
Cards do not show course dataConfirm that renderCourse(course) assigns card.course = course, and that the course setter stores the object and calls render().
Credits do not updateCheck that observedAttributes includes 'credits', and that the credits branch updates [data-credits].
The status switch does nothingConfirm that connectedCallback() adds the click listener and that handleStatusClick() calls setStatus().
Removed cards still respond to button clicks in testsConfirm that disconnectedCallback() removes the listener with the same bound handler reference.
The page count does not updateConfirm that status-change uses bubbles: true and composed: true, and that courseList listens for that event.
Setting status="Completed" dispatches an eventConfirm that attributeChangedCallback() calls setStatus(newValue, false) for the status attribute.
Unknown status values stay on the cardConfirm that setStatus() normalizes values with STATUSES.includes(value) ? value : null.

Conclusion

Section titled “Conclusion”

In this tutorial, we turned <course-info> into a stateful custom element. The page passes data in through the course property. The component stores private state, renders from that state, manages its own internal button listener with lifecycle callbacks, exposes a public setStatus() method, and dispatches a status-change event when meaningful status changes happen.

That creates a clean boundary. The page does not need to reach into the component’s Shadow DOM. It uses public properties, public methods, attributes, and custom events.
