[Later that day, Stewart receives an email…]

There are certain core pieces of information that need to be present in any course evaluation plan. In its simplest form, a course evaluation plan is a set (or array) of evaluation items. Each evaluation item must have at least the following: A name and a weight. For example, in this course the evaluation plan consists of five items.

  • Quizzes - 20%
  • Assignment 1 - 20%
  • Assignment 2 - 20%
  • Assignment 3 - 20%
  • Assignment 4 - 20%

When it comes to the marks assigned for each evaluation item, there are two more pieces of information: The number of points earned and the total possible points on the evaluation. The values for these are unknown at the start of the course (particularly from the student’s point of view); these only get disclosed as the course progresses.

Thus, it is possible for a particular student to have the following grades part-way through the course.

NameWeightPoints TotalPoints Earned
Quizzes203023
Assignment 1202620
Assignment 2202017
Assignment 32042
Assignment 420

From this, all other grade information can be calculated:

  • The total weight is 100% (which is required)
  • Percentages can be calculated for each evaluation item
  • You can calculate the trending average for all the completed/marked evaluations
  • You can calculate how much has actually been earned towards the final grade
  • You can calculate how much of the remaining weight is unmarked to date

All of this makes the tracking of your course grades an excellent example for Test-Driven Development.

The rules around the data are as follows.

  • Evaluation items
    • Must be valid
      • Name/Weight required
      • Weight between 1 and 100 inclusive
      • Total Points greater than zero
      • Earned points between 0 and the Total Points
      • Total Points and Earned Points can be null
      • Total Points cannot be null if there are Earned Points
    • Must total to 100$ in weight

Key Takeaways

Section titled “Key Takeaways”

A course evaluation plan is made up of evaluation items. Each item has:

  • a name
  • a weight
  • a pointsTotal value
  • a pointsEarned value

At the start of a course, some point values may be unknown. For example, a future assignment may have a weight, but no total points or earned points yet.

The course evaluation plan for this scenario contains five evenly weighted items:

  • Quizzes - 20%
  • Assignment 1 - 20%
  • Assignment 2 - 20%
  • Assignment 3 - 20%
  • Assignment 4 - 20%

The full plan must have a total weight of 100%. As marks are completed, the system should eventually be able to calculate item percentages, earned weight toward the final grade, outstanding unmarked weight, and a trending average over marked evaluations.

For this lab, most of your required working implementation will focus on validating individual evaluation items. The remaining suites are there so you can practice planning a broader set of tests without having to complete the entire grade-tracking system today.

Requirements

Section titled “Requirements”

Your validation tests and EvaluationItem code should be based on the scenario rules.

An evaluation item should account for these requirements:

  • name is required and cannot be empty.
  • weight is required.
  • weight must be between 1 and 100 inclusive.
  • Numeric values cannot be negative.
  • pointsTotal can be null.
  • pointsEarned can be null.
  • pointsTotal must be greater than zero when it is supplied.
  • pointsEarned cannot be supplied when pointsTotal is null.
  • pointsEarned cannot be greater than pointsTotal.
  • pointsEarned can be 0 when pointsTotal is greater than zero.

Your tests should be specific enough that a reader can tell which requirement is being checked. Avoid tests that pass without proving anything useful.

Your code does not need to be fancy. It does need to be clear, connected to your tests, and reasonable for the requirements you are claiming to satisfy.

Working With TDD

Section titled “Working With TDD”

You are expected to make reasonable use of a TDD workflow:

  3. Run the tests and confirm the new test fails for the right reason.
  4. Implement enough EvaluationItem code to satisfy that test.
  5. Repeat until you have at least 8 working validation tests.
