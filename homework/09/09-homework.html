Guided Self-Study Tutorial

Section titled “Guided Self-Study Tutorial”

In the previous lessons, we’ve written functions that organize work inside a single JavaScript file. In this self-study tutorial, we’ll take the next step: separating a small program across several files.

This is one way programmers apply separation of concerns. Instead of putting display code, calculation code, and command-line input handling all in one place, we can separate those responsibilities into modules.

By the end of this tutorial, we’ll have a small Assignment 1 bucket calculator that accepts marks on the command line and prints a formatted report.

  • practice.js The main entry point that coordinates the application
  • console-ui.js Handles user-display functionality
  • bucket-calculator.js Handles assignment bucket calculations

What’s important here is that console-ui.js knows nothing about bucket assignments, and bucket-calculator.js knows nothing about what user interface we’re working with. The top-level file, practice.js, imports the other modules and knits the application together.

Named Exports vs Default Export

console-ui.js uses named exports, so we imported them with import * as ui. bucket-calculator.js has a default export, so we import that one main value with import calculator from './bucket-calculator.js';.

Conclusion

Section titled “Conclusion”

You’ve now practiced using ES Modules to separate a program into different concerns. console-ui.js handles display, bucket-calculator.js handles calculation, and practice.js coordinates the whole script.

You also practiced using process.argv, which is one way Node scripts can receive information from the command line. This is a small example, but the pattern is important: one module can focus on input, another can focus on calculation, and another can focus on output.

Understanding JavaScript Modules

Modules help us keep related code together. When each file has a clear responsibility, the program is easier to read, test, change, and explain.
