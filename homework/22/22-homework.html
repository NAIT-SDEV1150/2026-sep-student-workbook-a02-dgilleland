Styling Course Info Cards

Guided Self-Study Tutorial

Section titled “Guided Self-Study Tutorial”

In the previous custom elements homework, we built a reusable <course-info> element for a small course catalogue. In this self-study tutorial, we’ll keep working with that same idea, but we’ll focus on styling.

Shadow DOM creates a styling boundary. That boundary is useful because it lets a component protect its internal markup and styles. At the same time, a reusable component usually needs a few intentional styling hooks so the page can adjust its appearance. We’ll practice that balance by exposing CSS custom properties, styling slotted content, and using part attributes.

Find the Styling Boundary

Section titled “Find the Styling Boundary”

Open ~/homework/22/practice/js/course-info.js and ~/homework/22/practice/css/styles.css.

The component has CSS inside the <template> in js/course-info.js. Those styles live inside the custom element’s Shadow DOM. The page stylesheet in css/styles.css can style the <course-info> host element directly, but it cannot freely reach into the component’s internal markup.

That boundary is the point of this practice.

In this tutorial, we’ll use four styling tools:

  • :host to style the custom element from inside its own Shadow DOM
  • CSS custom properties to let the page pass theme values into the component
  • ::slotted(...) to style light-DOM content assigned to slots
  • part attributes and ::part(...) to expose specific internal pieces for page-level styling

Common Styling Hook Problems

Section titled “Common Styling Hook Problems”

If something is not working, use the symptom to narrow down the problem.

SymptomWhat to check
The cards do not follow the page themeConfirm that css/styles.css defines --course-info-* values on course-info, and that js/course-info.js reads them with var(--course-info-..., fallback).
The featured card does not look differentCheck that the HTML or JavaScript sets variant="featured", and that the component stylesheet includes :host([variant="featured"]) .card.
Slotted text styles are not detected by testsCheck the exact selectors: ::slotted([slot="course-code"]), ::slotted([slot="course-name"]), ::slotted([slot="requisites"]), and ::slotted([slot="description"]).
::part(...) styles do nothingConfirm that the internal template has matching part attributes, such as part="credits" on the credits badge.
The theme button changes text but not colorsConfirm that the handler sets document.documentElement.dataset.theme to 'dark' or 'light'.
The credits button does nothingConfirm that creditsDemo selects #credits-demo and that the handler calls creditsDemo.setAttribute('credits', ...).

Conclusion

Section titled “Conclusion”

In this tutorial, we kept <course-info> encapsulated while still making it customizable. We used :host for internal component styling, CSS custom properties for theme values, ::slotted(...) for assigned light-DOM content, and part attributes with ::part(...) for controlled page-level styling of internal Shadow DOM pieces.

That is the balance Shadow DOM asks us to think about: keep internal markup private by default, and expose only the styling hooks the page is supposed to use.
